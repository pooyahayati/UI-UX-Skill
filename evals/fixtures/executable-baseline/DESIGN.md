# Dispatch Notes fixture design handbook

Canonical path: DESIGN.md. Writer: fixture author for the frozen baseline; continuation contributor writes only a prepared output copy. Baseline/document revision: fixture-h1. Sample: fixture-primary-1, source index.html. Lifecycle: accepted only within the explicitly fictional scope of fixture-owner-1 in OWNER_NOTES.md. Exact source and handbook hashes: BASELINE.json. No historical or real customer approval is asserted.

## Scope and authority

BRIEF.md owns the allowed job and protected behavior. English/LTR/light is the sole active context; phone-first responsive browser layout also supports desktop. No admin/runtime appearance settings, other locales, dark derivation, tracking, new role, dependency or backend is authorized. Existing native completion confirmation is retained. Routine mechanical decisions stay within the delegated feedback-copy scope.

## Foundation and actual value source

Executable values live in index.html's semantic CSS properties and component rules: balanced density, system typography, shared spacing/radius and text actions. This handbook links that single source; it is not an independently editable token or runtime settings database. System-font identity and real/synthesized weight have not been inspected. No font assets or external network dependencies are supplied.

## UX and state coverage

Assigned visit -> open instructions/editor -> edit draft -> simulated save -> retry on failure or completion confirmation. Editing clears the saved state. Failure retains the text. Saving is page-memory-only and refresh loses the draft; baseline successful-save wording omits that refresh consequence. The new request is a local disclosure need, not permission for a new persistence feature. All records/actions are synthetic and real server authorization/persistence are untested.

## Review and revision boundary

The baseline record names the exact source/handbook pair. A continuation must retain fixture-h1 and its provenance, identify only the changed feedback decision, assign a new source/handbook revision, and record actual checks separately from plans/unavailable checks. Delegation permits the named copy detail; it does not visually approve the generated screen or certify the whole product. Unchanged foundations/approval scope may be reused; no duplicate foundation interview or automatic dark/secondary generation.
