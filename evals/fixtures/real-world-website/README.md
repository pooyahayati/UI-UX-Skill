# Real-World Website Fixture

Representative product: bilingual service-business website.

Primary route: `website`

Intentional issues:

- navigation mirrors internal departments instead of visitor intent
- hero uses vague generic copy
- fake-looking trust statistics have no source
- every section is a card
- contact form asks for excessive data and uses placeholder-only labels
- no useful form error/success recovery
- oversized hero image and layout shift risk
- headings are visually styled but semantically weak
- mobile navigation and RTL behavior are incomplete
- raw palette values bypass semantic theme roles

Expected evaluation:

- route Website, not Web Application
- identify service-business visitor job and conversion
- use Website trust/conversion/SEO/media rules
- load relevant Shared forms/navigation/state/accessibility/responsive rules
- apply typography/color/component-state design-system contracts
- avoid fabricated proof and dark-pattern conversion
