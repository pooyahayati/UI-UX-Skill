This is a proposed contract for the existing appearance system. Product/platform evidence is unspecified, so routing is `generic-product-ui`; no platform pack or animation library is selected.

Extend the existing Motion section with these supported controls:

| Control | Supported behavior |
| --- | --- |
| Motion level | Off, Subtle, Standard, preserving accepted equivalent preset identifiers and the approved default. Off removes all animated transitions, including fades; Subtle provides restrained state feedback; Standard uses approved treatments. |
| Personal motion preference, if already permitted | Inherit or reduce the owner ceiling; never increase it. Existing authorization and account/tenant scope remain authoritative. |
| Preview, discard, reset | Private preview; discard leaves publication untouched; scoped reset prepares known defaults as a draft for validation and publication. |

Do not add the requested custom JavaScript field or unrestricted duration slider. Keep duration, easing, displacement and supported bounds in versioned design-system source. Owners select prepared presets. Preserve the current default; if none exists, propose Subtle only after confirming a task-heavy web context.

Resolve one shared policy across actual consumers. Owner Standard plus OS reduced uses reduced treatment; owner Off plus user Standard remains Off; user Off remains Off. OS reduction applies without a personal-settings page. React/provider reduction alone does not implement Off for CSS, fades, icons or independent animation drivers. Start with a usable static state until preferences resolve; apply changes during active transitions immediately.

Bind each draft to its author, existing scope and base published revision. Use Edit Draft → Preview → Validate → Publish. Enforce read/write permissions at the trusted boundary. Another administrator must not receive the private draft through previews, APIs or caches. Publish one complete validated snapshot atomically. A stale base returns a conflict: preserve both administrators’ work, display differences and require explicit reconciliation of overlapping fields. A lost publish response means unknown outcome; inspect the active revision before retrying.

Version persisted settings. Preserve valid older presets, migrate equivalent renamed values explicitly, and fall back for removed/corrupt/disallowed values without silently changing meaning. Reconcile personal preferences after publication and rollback. Retain reconstructable history. Rollback requires permission, current-schema validation and a new active revision with actor/time/change audit information.

Proposed acceptance checks, all unperformed:

- Exercise real panel preview, discard, publish, refresh/reopen, reset and rollback; confirm every claimed consumer changes and reverses without component edits.
- Deny unauthorized/cross-scope access; prove private-draft isolation with two administrators and public sessions; reject unknown presets and executable values server-side.
- Race publications from one base; verify conflict recovery, preserved unrelated edits, atomic publication, cache invalidation and uncertain-response reconciliation.
- Load older, missing, partial, corrupt and unavailable configuration. Retain a safe last-valid/default policy, distinguish fallback from published/preview state, offer recovery and never strengthen effective motion or leak a draft.
- Test owner/user/OS combinations, live preference changes, repeated/interrupted actions, keyboard/focus/overlay cleanup and truthful pending/error/success. Actions and cleanup must not depend on animation callbacks.
- Inspect supported narrow/wide, theme and direction contexts; measure performance if scope adds substantial motion or dependencies.

Before implementation, inventory real consumers and record labels, defaults, permissions, preset/token sources, adapters, migration and reset behavior in existing `DESIGN.md`.
