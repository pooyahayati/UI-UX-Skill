Use one resolved motion policy across every consumer. The owner's setting is a ceiling; a personal preference may lower it, and OS reduced motion is a protected constraint.

| Situation | Effective behavior |
| --- | --- |
| Owner standard; OS reduced motion enabled | Reduced treatment, even if the user selected standard. |
| Owner off; user standard | Off. A user cannot exceed the product ceiling. |
| User off | Off regardless of owner level or OS preference. |

Offer the existing approved off/subtle/standard presets, preserving equivalent saved choices. Do not interpret subtle as automatically satisfying OS reduction. Resolve the permitted owner/user level first, then apply the OS reduction treatment unless already off.

Under reduced motion, remove large movement, parallax and repetitive loops. Use immediate changes or brief non-spatial feedback where useful. Under off, eliminate all animated transitions, including fades, icon morphs and loader rotation. Preserve immediate state changes, readable status, focus and every action.

For loading, replace spinning or shimmering indicators with static artwork and a visible “Loading…” status; expose busy/status semantics appropriately. Do not invent percentages or infer completion from elapsed animation time. Animated icons retain accessible control names and truthful expanded/pressed/status states, with prepared static artwork for each state and provider failure.

Resolve policy once through the existing token/configuration boundary. Apply it to CSS transitions/keyframes and pseudo-elements, component animation providers, imperative drivers, icons, and overlay/portal roots outside the main tree. Explicitly bridge independent roots or consumers rather than assuming context or CSS inheritance reaches them. If Motion is already used, its OS reduction setting alone is insufficient: it may retain opacity animation and does not implement product-wide off.

Observe OS preference on initial render and subscribe to changes. Until client preferences/configuration are known, render a static usable state without an initial animation burst; retain server/client markup compatibility. Invalid or failed configuration must fall back without enabling stronger motion than permitted.

If reduction activates while a sheet closes, immediately cancel/settle its active animation to the correct closed state. Changing only future animation options is insufficient. An idempotent close lifecycle must remove the overlay and input interception, release scroll locking/background restrictions, and return focus meaningfully. Ignore stale completion callbacks; prevent duplicate actions and preserve drafts. Never depend solely on animation-end events or exit callbacks for cleanup, navigation, validation or mutations. If restrictions relax mid-close, finish closing without replaying entrance/exit effects. Clean up subscriptions and drivers on unmount.

Keep owner changes within existing authorized draft, private preview, validation, publication, history, reset and rollback. Reject invalid presets at the trusted write boundary; expose the effective restriction clearly without silently rewriting valid stored intent.
