Resolve one motion policy for the whole product. The owner's setting is a ceiling; a user's preference may reduce it, and the operating system's accessibility preference remains binding. These are constraints, not a last-setting-wins sequence.

| Situation | Required behavior |
| --- | --- |
| Owner selects standard; OS requests reduced motion | Apply the reduced-motion treatment. Remove large movement, layout travel, parallax and looping effects. Use immediate state changes or a brief non-spatial alternative where useful. A personal standard preference cannot override this. |
| Owner selects off; user prefers standard | Off. The user cannot raise the owner's ceiling. |
| User selects off | Off, regardless of the owner or OS setting. |
| Owner permits standard; user selects subtle; OS has no reduction request | Subtle. |
| Owner and user permit standard; OS has no reduction request | The approved standard preset. |

“Reduced” is an accessibility treatment, not merely a synonym for the subtle branding preset. “Off” is stronger: remove every animated transition, including opacity fades, while keeping all actions and state information available.

Keep the stored preference separate from its effective result. For example, a valid stored standard preference may currently resolve to off under the owner ceiling. Show the effective value and its reason in the panel without silently rewriting that preference. Validate removed options or newly locked fields against the current schema and use a safe fallback when necessary.

The shared policy must reach every consumer:

- **Component transitions:** consume approved semantic motion presets through the existing theme/configuration boundary. Do not let component-local defaults raise the effective level.
- **CSS loaders and transitions:** apply the resolved policy to their actual styles, including pseudo-elements. Reduced mode replaces looping spinners, shimmer and pulsing with a static waiting indicator and understandable status text. Off also removes fades. Keep pending status, measured progress where available, and completion/error announcements; stopping animation never means that the operation completed.
- **Animated icons:** retain their semantic meaning, accessible names and state pairs. Use meaningful static pending/success/error/expanded alternatives when reduced or off; do not leave an icon frozen at an ambiguous intermediate frame.
- **Sheets, dialogs, tooltips and other overlays outside the main tree:** explicitly connect their portal/container or independent root to the same policy. A provider on the main component tree or CSS variables on its wrapper may not reach them. Include backdrop, content, exit animation and any third-party primitive adapter.
- **Imperative or independent engines:** forward policy changes and cancel/settle active effects through their supported interfaces. A library's reduced-motion option is not evidence that CSS, icons or other engines comply. A provider may still permit opacity animation, so it is insufficient by itself for off mode.

Read the OS preference before starting effects and subscribe to changes. While preferences or configuration are unknown, render a static, usable initial state so there is no initial animation burst. Invalid or failed configuration loads must retain a safe last-valid/default policy and must never defeat a known user-off or OS-reduced request.

If the OS preference changes while a sheet is closing, recompute the policy immediately. When reduction becomes active, cancel the remaining spatial exit and settle directly to the intended closed state; do not replay the exit. If reduction is lifted during that close, finish the current safe close without introducing stronger motion midway; use the newly resolved policy for subsequent interactions.

Closing must be an idempotent semantic operation independent of animation completion. Use the overlay primitive's supported lifecycle to remove exiting content and backdrop, release its focus trap, scroll lock and background inertness, and restore focus to the trigger or another meaningful available target. No invisible overlay may intercept input, and hidden content must not remain keyboard-focusable. Do not depend solely on an animation-end event or exit callback: cancellation, disabled motion, unmounting and rapid close/reopen must settle correctly. Ignore obsolete completion callbacks so an earlier exit cannot close a newly reopened sheet. Preserve drafts and run any underlying operation only once.

Use the existing authorized draft, private preview, validation and publication flow for product settings, with history, reset and rollback. Reset must re-resolve current constraints rather than disable accessibility protection. Keep owner controls limited to the approved off/subtle/standard presets; there is no need for raw timings or a library selector.

Acceptance checks should exercise the table above through the real panel, then refresh/reopen and reverse the setting. Observe a CSS loader, animated icon and independently mounted sheet/backdrop in each policy. Toggle OS reduction during opening and closing, test repeated close/reopen, keyboard dismissal and focus return, and verify pending/error/confirmed outcomes, configuration failure, private-preview isolation and rollback. Include the first render to catch motion flashes.

This is a behavioral specification for a targeted web-application interaction. It uses the Web Application interaction module, shared motion/accessibility rules and runtime preference governance; unrelated product packs and visual foundations are outside scope. No implementation, rendered interaction or automated check was supplied or executed, so runtime conformance remains unverified.
