The current preset does not fulfill an **off** promise. Treat motion as an optional presentation layer over a complete interaction state model. Disabling or interrupting animation must leave the same usable form, authoritative save result, and correct focus.

### Design contract

- **Off:** no animated transitions, including opacity fades, skeleton shimmer, animated icons, or looping loaders. Content appears in its usable final state immediately. Retain static loading placeholders, meaningful “Saving…” text, busy semantics, validation messages, and persistent result feedback.
- **Reduced:** remove large movement, parallax, and loops; use immediate changes or an approved brief non-spatial alternative when helpful. Reduced and off are distinct contracts.
- **Normal presets:** motion may explain a transition, but never delay focus, validation, submission, access to essential content, or the next task. Do not invent progress percentages or impose a minimum animation-length wait.

Resolve one effective policy across the application. The owner preset is a ceiling; personal preferences can lower it, and the operating system’s reduced-motion preference must remain effective. Owner off plus user standard stays off. Owner standard plus OS reduced receives reduced treatment. Handle preference changes during an interaction, with a static usable initial state until preferences resolve.

### Implementation contract

`MotionConfig reducedMotion="always"` is insufficient: documented reduction removes transform/layout motion while values such as opacity can remain animated; it also does not govern unrelated CSS or imperative consumers. Keep the existing provider, but make the resolved policy drive every affected consumer: CSS transitions/keyframes and pseudo-elements, Motion variants/layout/exit behavior, copied animated components, icons, skeletons, and independent animations.

For off, explicitly select static variants and disable transitions/keyframes; stop active animations and settle to the correct visual state. Do not merely pause a shimmer halfway through or leave content at its entry opacity. Avoid a tiny-duration workaround whose purpose is to trigger completion events. Reuse semantic tokens/adapters and the existing settings lifecycle; a preset must actually control the consumers it claims to control.

Separate interaction state from presentation completion:

- Opening a form/step commits its semantic state first. Place required focus after the destination is mounted and usable, through the component’s supported focus lifecycle. Show focus immediately. Validation failure reveals errors and, where appropriate, focuses the error summary or first invalid field without waiting for animation.
- Closing a dialog restores focus appropriately and releases traps, inertness, scroll locks, and blocking overlays independently of decorative exit completion. Exiting content must not remain keyboard-interactive. Interrupted transitions must not leave an invisible blocker.
- Saving follows explicit states such as editing, validating, pending, confirmed success, failure, and uncertain outcome. Only authoritative acknowledgement establishes “Saved.” If acknowledgement represents a queued job, show queued/processing instead. Announce meaningful result changes accessibly without moving focus for a passive success message.
- Animation callbacks may perform optional visual cleanup; they must not be the sole trigger for mutations, validation, navigation, focus, or result reporting. Any necessary fallback cleanup must be bounded, idempotent, and harmless if its callback also fires.

### Timeout and rapid repeated clicks

Keep the request deadline separate from animation duration. On timeout, preserve field values and explain that confirmation was not received. A client timeout or abort does not prove that the server rejected or rolled back the save. Show an uncertain outcome when appropriate, check authoritative status where supported, and offer a safe recovery path. Never turn a timer into a success confirmation.

Guard submission synchronously at the action boundary, before awaiting anything, so two clicks or Enter presses in the same render cycle cannot start two saves. Expose the pending/busy state and suppress duplicate submissions while the same operation is unresolved; a visual disabled state or debounce alone is insufficient. Use an operation identity and server idempotency where supported, preserving that identity when retrying the same uncertain operation. Otherwise reconcile before offering a potentially duplicate retry.

Associate responses with the submitted revision. A late response from an older attempt must not overwrite newer edits, clear the current dirty state, or report those newer edits as saved. For steps/disclosures, define coherent interruption behavior: settle to the latest valid intent, preserve drafts, and never let repeated activation skip required validation. Cancel obsolete animation work and clear timers/listeners on unmount; stale callbacks must not steal focus or mutate a replacement view. Consolidate repeated notices.

### Acceptance evidence

Exercise the actual form and save path under normal, reduced, and off policies. Verify CSS fades and shimmer as well as provider-controlled motion. Change preferences mid-transition; suppress animation callbacks entirely; test slow responses, validation failure, confirmed failure, timeout followed by late success, repeated click/Enter activation, retry, and navigation away. Check request counts, preserved drafts, correct revision/result messaging, immediate keyboard focus, announcements, and absence of hidden blocking overlays. In off mode, essential behavior must still work when no animation event ever fires.

Record the preset definitions, affected consumers, focus/state rules, timeout/retry policy, and evidence gaps in the existing design and implementation documentation. Preserve permissions, validation, persistence/history, and the panel’s existing preview/publication boundaries.
