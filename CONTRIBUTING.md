# Contributing

Improve agent decisions with bounded, evidence-backed changes. Start with the [roadmap](ROADMAP.md): completed R0–R8/R9 exceptions do not authorize unrelated capabilities.

## Source and scope

Canonical Skill source: `skills/ui-ux-skill/`. Do not add duplicate root copies of `SKILL.md`, `agents/` or `references/`; packages are generated by `scripts/package_release.py`.

Useful maintenance spans all supported products: routing/isolation, audit and regression behavior, accessibility/RTL, workflow recovery, trustworthy data, design-system consistency, safe appearance governance and documentation.

Preserve product semantics, permissions, business logic and existing stack. New Product Types, major capability families, external specialists or general-purpose builders need separate owner authority.

## Where a change belongs

- `SKILL.md`: shared entrypoint, essential constraints and conditional routing.
- Product Packs/local modules: product-specific guidance.
- Shared Rules/Design System modules: genuinely shared contracts and reusable foundations.
- `evals/`: raw inputs, separately labeled authored examples and concrete evidence.
- Root docs: concise entrypoints/current status; `docs/archive/`: dated detailed history, not another active instruction set.

Avoid generic tutorials, duplicate rules, universal visual preferences, speculative frameworks and arbitrary-code appearance controls.

## Verification

From the repository root:

```bash
python3 scripts/validate_release.py
python3 scripts/test_roadmap_policy.py
python3 scripts/test_package_release.py
python3 scripts/validate_eval_fixtures.py
python3 scripts/package_release.py --output <new-external-output-directory>
```

Use a nonexistent dedicated output under an existing parent; the packager refuses every existing destination, including empty directories, rather than deleting or replacing it. Prefer an external output; the only allowed in-repository destination is a fresh top-level `dist` for CI. Relative paths are relative to the repository, not the shell's working directory. See [packaging safety and limits](INSTALL.md#packaging-safety-and-limits). Run affected Product/Shared/Design/Specialist validators and relevant regressions; CI also runs the official Skill quick validator.

For meaningful behavior changes, use the [evaluation guide](evals/README.md) and `scripts/prepare_eval_run.py`; keep raw inputs separate from expected answers and validate actual recorded results with `scripts/validate_eval_result.py`. Structural checks are not model/rendered/owner-approval evidence.

For documentation moves, preserve source/evidence, update local links/anchors and keep current status separate from history. Do not weaken checks to make a rewrite pass.

## Pull requests

State the problem, bounded change, routing/compatibility impact, actual checks and remaining limits. Keep unrelated changes separate. Push, merge, release, deployment and installed-Skill updates each require their actual authorization.
