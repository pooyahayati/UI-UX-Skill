# Material runtime appearance — existing authority, connected consumers

Read only for selected Material and an actually authorized runtime appearance
change. Use [runtime governance](runtime-ui-governance.md) first. This is an
adapter over its prepared parameter/asset contract, not a second theme engine,
admin requirement, live handbook database, upload service or component library.
Audit-only remains read-only; a narrow correction stays narrow. No admin means
no invented backend/settings panel. Host appearance remains outside owned scope.

## Prepare meaningful controls, not arbitrary styling

| Existing parameter family | Material-sensitive consumers / protected boundary |
| --- | --- |
| Palette/theme | Resolve paired text, container, field, boundary, focus and action roles; include overlay and non-CSS consumers. Preserve the approved brand; no mandatory Google palette or dynamic-color service. |
| Available fonts and roles/sizes | Approved asset IDs/families, body/heading/label roles and readable ranges. Heading overrides must not silently replace body/chart text. Do not impose Roboto. |
| Density/spacing | Supported task-appropriate presets and responsive wrapping, with protected target/readability floors. Never reduce targets merely because icon artwork is small. |
| Border/shape/elevation | Owned containers, inputs, overlay and diagram adapters where applicable; inherit settled ranges. No universal rounding or shadow-only dark boundaries. |
| Existing component variants/motion | Only implemented variants; preserve semantics, requiredness, business states, confirmation, keyboard and system reduced-motion precedence. |
| Semantic icons | Available family/visual properties and per-use gallery, immutable meaning, accessible labels, state pairs, documented fallback and selective directional mirroring. |

Every offered choice needs a real consumer, validation, permission, preview,
publication and reversal path. Do not display a cosmetic selector whose value is
ignored. Typography roles may inherit rather than duplicate a current stack;
changing the body stack later must preserve that inheritance contract.

Material Symbols is optional. Offer it only after the host has approved and
prepared actual assets/dependency, licenses, rendering/state coverage and safe
fallbacks. Selecting a family is not permission for owner-authored SVG/code or a
remote asset URL. Retain the existing R6 icon resolver/registry rather than
copying markup into pages. Charts/tables/diagrams stay product-specific patterns,
not invented official M3 components.

## Source of truth and compatibility

`DESIGN.md` describes the approved intent, exposed/locked parameters, legal
bounds, affected consumers, implementation strategy, permissions and evidence.
The host catalog/defaults and validated runtime store own actual values. Routine
supported owner edits must not require source or handbook edits. The handbook
links a scoped result; it does not mirror every live value.

Reuse host sessions/authorization, actor/tenant/user precedence, settings store,
private preview, exact-draft publication, history and reset/rollback. Never trust
client role/tenant fields. Validate complete snapshots, allowlisted assets/enums,
bounded finite sizes and contrast/target floors before publication. Deny CSS/JS,
unsafe URLs/paths, invalid or unavailable values and injected authority. Preserve
recoverable user input and honest pending/error state.

For a contract extension, version the configuration, strictly validate each
supported prior schema, normalize complete valid snapshots on read, preserve old
values/history and default the new opt-in presentation to the observed baseline.
Reject incomplete/unknown/invalid data instead of partial merging. Keep old stored
bytes intact; rollback appends a new validated normalized copy. A stale client
reloads the current catalog before saving. Migration cannot quietly select a
Material style or replace an approved font.

Owner font upload remains a separately prepared production asset capability when
in scope: trusted ownership, supported format/content/size/license validation,
asset identity/version, private preview, fallback, publication and rollback.
Do not claim it exists in a fixture offering only available generic stacks.
For a Persian product retain default Vazirmatn unless an actual authorized font
decision changes it; preserve real language/direction and font-loading QA.

## Verify the existing lifecycle

Show actual connected controls/fields/headings, overlay, data adapter and icons
in a private draft while a public reader remains unchanged. Save, confirm
publication, refresh/reopen, then exercise private defaults and rollback. Verify
another actor/tenant cannot read/publish the draft; invalid or denied writes leave
published/draft/history unchanged. Test prior-schema history/drafts and stale
revision conflicts, not just fresh defaults.

Inspect representative compact/wide and theme-sensitive states from the actual
authorized product contexts. Keep geometry, trustworthy captures, keyboard,
contrast measurements, font identity and assistive-technology evidence separate.
Reuse [QA](qa-checklist.md) and [visual evidence](visual-regression.md). Material
does not bypass primary approval before a new dark design or create secondary
locales. Synthetic authorized theme tests are not real-product owner approval.

## Executable bounded reference

The repository's `evals/fixtures/runtime-appearance` and
`scripts/runtime_appearance.py` reuse the R5/R6 panel/store/HTTP/SVG consumers.
Schema 3 adds baseline/material surface treatment and an inherit/serif heading
role; schemas 1/2 normalize read-only. Baseline remains default. Material-derived
containers/fields and compact control floors inherit existing prepared palette,
font/size/spacing/shape/variant/motion/icon settings. The original outline/solid
families are not Material Symbols. This is a Material-inspired custom adapter,
not a claim of library conformity, production authentication or font-upload
implementation. Full optional-mode evaluation remains a separate R9.6 gate.
